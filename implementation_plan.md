# Implementation Plan

[Overview]
Add Laravel Form Request validation to `CrudBaseController::store()` and `CrudBaseController::update()` via abstract base Form Request classes (`CrudBaseStoreRequest`, `CrudBaseUpdateRequest`) and per-model concrete classes generated by the `GenerateCrud` command.

The package currently has zero validation — `store()` and `update()` blindly call `$this->crud_base_repository->create($request->all())` and `$this->crud_base_repository->update($id, $request->all())` without any input validation. This poses security and data integrity risks.

The approach uses Laravel's native Form Request pattern with a strict contract: two abstract base classes in the package namespace enforce the structure, and per-model concrete classes (`{Model}StoreRequest`, `{Model}UpdateRequest`) extend them. The generated controller overrides `store()` and `update()` with type-hinted concrete Form Requests, calling extracted base controller methods that accept already-validated data. The base controller's `store(Request)` and `update(Request, $id)` throw `BadMethodCallException` — forcing developers to override them. If a per-model Request class is missing, PHP's autoloader fails. If the controller override is missing, the runtime exception fires. No silent fallback anywhere.

[Types]
Two new abstract base classes in the package, and two concrete per-model classes generated into the host app. All extend Laravel's `FormRequest`.

**Abstract base — `src/Requests/CrudBaseStoreRequest.php`:**
- Namespace: `GT264\CrudFiesta\Requests`
- Extends: `Illuminate\Foundation\Http\FormRequest`
- `authorize(): bool` — returns `true`
- `rules(): array` — abstract, returns `array`

**Abstract base — `src/Requests/CrudBaseUpdateRequest.php`:**
- Namespace: `GT264\CrudFiesta\Requests`
- Extends: `Illuminate\Foundation\Http\FormRequest`
- `authorize(): bool` — returns `true`
- `rules(): array` — abstract, returns `array`

**Per-model concrete — `App\Http\Requests\{Model}StoreRequest`** (stub-generated):
- Extends: `GT264\CrudFiesta\Requests\CrudBaseStoreRequest`
- `rules(): array` — returns `[]` (empty array, developer fills in)

**Per-model concrete — `App\Http\Requests\{Model}UpdateRequest`** (stub-generated):
- Extends: `GT264\CrudFiesta\Requests\CrudBaseUpdateRequest`
- `rules(): array` — returns `[]` (empty array, developer fills in)

[Dependencies]
No new Composer dependencies. Laravel's `Illuminate\Foundation\Http\FormRequest` is already available via the `laravel/framework` dependency. No version changes. No new package requirements.

The autoloader already maps `GT264\CrudFiesta\` to `src/` via `composer.json` PSR-4, so `src/Requests/` is automatically covered.

[Testing]
No automated test files exist in the repository. Manual testing approach:

- **Abstract base commitment**: Verify that `CrudBaseStoreRequest` and `CrudBaseUpdateRequest` are abstract and cannot be instantiated directly.
- **Generation smoke test**: Run `php artisan crud:generate Post` and confirm `App\Http\Requests\PostStoreRequest.php` and `App\Http\Requests\PostUpdateRequest.php` are created with correct `extends` clauses pointing to the abstract bases.
- **Autoloader enforcement**: Attempt to call a route without the generated Request class — PHP autoloader must fail.
- **Controller override enforcement**: If `store()` or `update()` are called on a controller without overrides, `BadMethodCallException` must fire.
- **Validation smoke test**: Fill in `rules()` in a generated StoreRequest, submit invalid data via the form, and confirm Laravel rejects the request before the controller executes.
- **Stub placeholder verification**: Confirm that all `{{ }}` placeholders in the new stubs are correctly substituted by `GenerateCrud`.

[Implementation Order]
The implementation sequence minimizes conflicts and allows incremental testing after each step.

1. Create `src/Requests/CrudBaseStoreRequest.php` — abstract base Form Request for store
2. Create `src/Requests/CrudBaseUpdateRequest.php` — abstract base Form Request for update
3. Create `src/Stubs/StoreRequest.stub` — stub extending `CrudBaseStoreRequest`
4. Create `src/Stubs/UpdateRequest.stub` — stub extending `CrudBaseUpdateRequest`
5. Refactor `src/Controllers/CrudBaseController.php` — extract `storeItem()` and `updateItem()`, change `store()` and `update()` to throw `BadMethodCallException`
6. Update `src/Stubs/CrudController.stub` — add Form Request-typed `store()` and `update()` overrides calling `storeItem()` / `updateItem()`
7. Update `src/Helpers/GenerateCrud.php` — add namespace substitutions and stub processing for the two new request stubs
8. Manual verification — run `php artisan crud:generate {ModelName}` and inspect all generated files
